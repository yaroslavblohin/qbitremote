# Правила выпуска

- При каждом завершённом наборе изменений повышать версию приложения. По умолчанию увеличивать patch-компонент на один; если пользователь указал версию, использовать её. Не увеличивать версию отдельно на каждый файл или промежуточную правку одной задачи.
- Синхронно обновлять версию пакета qbit-remote в Cargo.toml и Cargo.lock, текущую версию в README.md и запись в CHANGELOG.md. Интерфейс получает версию из CARGO_PKG_VERSION.
- Перед заменой dist/qbit-remote.exe копировать существующий бинарник в dist_backup/qbit-remote-<старая-версия>-<дата-время>.exe. Архивировать именно ранее выпущенный файл, не новую сборку. Не перезаписывать существующие архивы; проверять совпадение SHA-256 исходника и архивной копии.
- После успешной release-сборки обновлять dist/qbit-remote.exe. В dist оставлять только один EXE. Если файл занят, не завершать пользовательский процесс принудительно и не создавать дополнительные версии в dist; сообщить о необходимости штатного выхода.
- Папка dist_backup исключена из Git. Не удалять архивы без явного запроса пользователя.
- При каждом выпуске обновлять Release/qbit-remote.exe той же сборкой, что и dist/qbit-remote.exe, и Release/README.md с текущей версией и инструкциями для пользователя. README в Release должен быть самостоятельным, без ссылок на отсутствующие в этой папке файлы и изображения. Проверять совпадение SHA-256 бинарников в dist и Release. В Release держать один актуальный EXE и README.
