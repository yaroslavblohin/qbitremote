# Проверки qBit Remote 0.2.39

Дата: 1 ноября 2026 года. Платформа: Windows, Rust MSVC, egui/eframe 0.31.1. Другие ОС не проверялись.

## Автоматические проверки

| Проверка | Результат |
| --- | --- |
| `cargo test --locked --all-features` | 85 прошли, 0 ошибок, 6 исключены из прямого запуска. |
| `cargo clippy --locked --all-targets --all-features -- -D warnings` | Без предупреждений. |
| `cargo fmt --check` | Форматирование соответствует проекту. |
| `scripts/test-shell-open.ps1` (выпуск 0.2.30) | По два сценария на локальном и сетевом пути: разрешение пути списка торрентов и дерева файлов, реальный запуск Windows Shell в короткоживущем потоке, обнаружение окна Проводника по полному пути после выхода потока. |
| `scripts/test-tray.ps1` (выпуск 0.2.26) | Три сценария, в каждом 10 циклов закрытия в трей и восстановления и 10 циклов скрытия/показа левым щелчком. Правая кнопка не меняет видимость; двойной щелчок не переключает окно повторно; свёрнутое окно восстанавливается. Штатное сохранение и выход из скрытого, открытого и свёрнутого окна. |

Из шести исключённых тестов три требуют явно заданных учётных данных реального сервера. Ещё один открывает Проводник и запускается отдельно через `scripts/test-shell-open.ps1`. Два других — вспомогательные дочерние процессы: они запускаются и проверяются родительскими тестами защиты от второго экземпляра и передачи файлов. Три исключённых API-теста рабочего сервера в этом наборе не запускались; изменения торрентов и настроек проверялись через локальный HTTP mock-сервер. Отдельно прочитаны реальные save_path, content_path и список файлов одного торрента для проверки соответствия доступной сетевой папке; серверные данные не изменялись.

Нативный GUI-сценарий с `$env:QBIT_SMOKE_PAGE='path-mappings'` и `cargo run --locked --features ui-smoke` также завершился штатно; снимок `docs/path-mappings.png` проверен визуально. Использовались демонстрационные пути, без подключения к сетевым ресурсам.

Геометрия диалога и щелчки проверяются непосредственно в egui, без сетевого сервера. Нативная проверка трея запускает отдельный Windows-процесс в демонстрационном режиме; штатный клиент пользователя не завершается. События мыши программно передаются производственному обработчику. Настоящие клики по значку и показ меню не автоматизированы; для ручной приёмки левый щелчок должен переключать окно без меню, правый — открывать меню без переключения окна.

## Демонстрационные окна и снимки

`scripts/update-screenshots.ps1` создаёт 15 кадров текущей версии: список торрентов, файлы, скорость, Graphite, White, контекстное меню, множественный выбор, импорт RSS и диалог добавления, а также отдельные снимки сопоставлений, открытия файлов и строки состояния. Они используют фиктивные данные; пароль и настройки рабочего сервера не нужны.

Для выпуска 0.2.39 все 15 кадров сформированы заново. Название темы в интерфейсе и документации — Marine Dark Theme; формат сохранённого выбора Marine не изменялся. В выпуске 0.2.25 дополнительно проверены окно высотой 650 точек с 205 файлами в Graphite и окно высотой 360 точек в White при масштабе 150%: кнопки доступны, область файлов меняет высоту, цветные подписи приоритетов читаются. Снимки этих двух сценариев сохранены в `dist/test-dialog-large.png` и `dist/test-dialog-hidpi.png`; это генерируемые материалы проверки, не часть папки Release.

Чтобы проверить высокий диалог с 205 демонстрационными файлами:

```powershell
$env:QBIT_SMOKE_PAGE = 'add-torrent'
$env:QBIT_SMOKE_ADD_MANY = '1'
$env:QBIT_SMOKE_ADD_HEIGHT = '650'
$env:QBIT_SMOKE_ZOOM = '1'
$env:QBIT_SMOKE_THEME = 'graphite'
Remove-Item -LiteralPath dist/ui-smoke-state.ron -ErrorAction SilentlyContinue
cargo run --locked --features ui-smoke
```

Для маленького окна при увеличенном масштабе задайте высоту `360`, масштаб `1.5` и тему `white`, снова очистите тестовый файл состояния и повторите запуск. Снимок сохраняется в `dist/ui-smoke.png`; тестовое окно завершается автоматически. Эти переменные относятся только к сборке с `ui-smoke`. Файл `dist/ui-smoke-state.ron` содержит исключительно состояние демонстрационного окна.

После ручной проверки удалите переменные `QBIT_SMOKE_PAGE`, `QBIT_SMOKE_ADD_MANY`, `QBIT_SMOKE_ADD_HEIGHT`, `QBIT_SMOKE_ZOOM` и `QBIT_SMOKE_THEME` из текущей сессии PowerShell. Скрипт обновления снимков сохраняет и восстанавливает прежние значения сам.

## Границы проверки

Тесты HTTP проверяют кодирование и последовательность запросов, ответы и отказы API, но не заменяют приёмку загрузки на конкретной версии сервера. Предварительный выбор файлов требует qBittorrent 5.2+ с API метаданных. Выбор новых данных для фактического скачивания на рабочем сервере в рамках этих дополнительных проверок не выполнялся.

Открытие реального файла через ассоциацию Windows не автоматизировано. Доступ к папке SMB проверен отдельным нативным сценарием выпуска 0.2.30. Для ручной приёмки задайте доступное сопоставление, откройте существующий файл, папку и содержащую папку, затем проверьте ошибку для недоступного пути и смену профиля.

В выпуске 0.2.28 нативный GUI-сценарий с `$env:QBIT_SMOKE_PAGE='actions'` и `cargo run --locked --features ui-smoke` завершился штатно. Команды «Открыть папку» и «Открыть файл» в основном контекстном меню проверены визуально; снимок — `docs/torrent-open-menu.png`. Ассоциации Windows и доступ к пользовательским сетевым ресурсам требуют ручной приёмки.

В выпуске 0.2.29 нативный `cargo run --locked --features ui-smoke` проверен визуально с обычным масштабом и с `$env:QBIT_SMOKE_ZOOM='1.5'`, `$env:QBIT_SMOKE_FREE_SPACE='524288000'`: показатели не перекрываются, критический остаток выделяется красным, оба сценария завершаются штатно. Снимок обычного масштаба — `docs/status-bar.png`.

## Проверка открытия Проводника (0.2.30)

```powershell
./scripts/test-shell-open.ps1
# Существующий ресурс: укажите свои пути, файлы на ресурсе не изменяются.
./scripts/test-shell-open.ps1 -LocalRoot 'Y:\torrents\complete' -ServerRoot '/downloads/complete' -RelativeFolder 'Имя папки торрента'
```

Скрипт по умолчанию создаёт уникальные пустые папки в `dist`, запускает нативный тест из нового фонового потока и через Shell.Application проверяет реальное окно Проводника. Временные папки и созданные им окна убираются; ранее открытые окна пользователя не закрываются. С параметрами существующая папка только открывается, файлы ресурса не создаются и не удаляются.

Оба входа прошли на локальной папке с пробелами, кириллицей и амперсандом и на доступной папке подключённого SMB-диска. Проверка подтверждает открытие папок, но не запускает реальные пользовательские файлы и не проверяет все установленные ассоциации Windows. Для ожидания передачи запроса из потока без message loop используется [SEE_MASK_NOASYNC (Microsoft)](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/ns-shellapi-shellexecuteinfow).

Системные пиктограммы запрашиваются по расширению с SHGFI_USEFILEATTRIBUTES в фоновом потоке; реальные файлы торрента не читаются. Обоснование API: [SHGetFileInfoW (Microsoft)](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shgetfileinfow). Значки неизвестных типов зависят от установленных ассоциаций Windows; индивидуальные значки внутри EXE и миниатюры содержимого не извлекаются.

В выпуске 0.2.32 файловые деревья проверены визуально в Marine Dark, Graphite и White; в диалоге добавления одновременно видны открытая и закрытая папки и значки типов файлов. Нативный GUI со значками при масштабе 150% завершился штатно; размеры системных текстур при 100–300% проверены отдельным автоматическим тестом. Все 12 снимков документации обновлены.

В выпуске 0.2.33 компактная кнопка папки проверена визуально в одной строке с поиском и командами дерева в Graphite, Marine Dark и White. У кнопки есть подсказка и доступное имя; обработчик открытия не изменён.

В 0.2.34 значок кнопки открытия папки переработан по образцу пользователя: жёлтая папка со светлыми листами. Проверен визуально на штатном размере в темах Graphite, Marine Dark и White; отрисовка векторная. Поведение открытия и сопоставления путей не менялось.

В 0.2.35 регрессионный тест передаёт завершённые результаты фонового открытия через настоящий канал: успех и отмена не добавляют информационную строку и сохраняют сообщения других операций; ошибка остаётся видимой. Системные приложения в этом тесте не запускаются. Скриншоты интерфейса остаются от 0.2.34: изменение касается только отсутствия уведомления после действия.

В выпуске 0.2.36 новый логотип qb с пультом проверен в боковой панели во всех темах. PNG 512/32/16 пикселей экспортированы из общего исходника `src/icon_pixels.rs`, который также формирует ресурс EXE, значки окна и трея. Прозрачность и размеры экспортов проверены; 12 скриншотов пересозданы.

В 0.2.37 цветные пиктограммы проверены в верхней и нижней части меню. Сценарий `actions-bottom` открывает меню и прокручивает его штатным событием колеса; снимок — `docs/screenshots/actions-bottom.png`. Проверены палитры Graphite, Marine Dark и White и увеличенная шапка с логотипом 42 точки. Поведение команд не менялось; существующие UI-тесты проверяют доступность действий.

В 0.2.38 карта частей и график торрента проверены визуально через демонстрационные сценарии `pieces` и `torrent-graph`. Зелёные готовые, синие загружаемые и серые отсутствующие сегменты различимы; графики используют линии толщиной 1 точку. Порядок вкладок изменён без изменения их идентификаторов и API-маршрутов.

В 0.2.39 проверено отображение зелёной раздачи в таблице: статус, прогресс и скорость отдачи. Снимки пересозданы на демонстрационных данных во всех трёх темах.
